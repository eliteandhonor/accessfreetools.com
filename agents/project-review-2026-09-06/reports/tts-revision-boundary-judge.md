### Native Cache Binding

For the native browser Cache API, `proposedCacheKey` is the full `remoteURL`, so the template binds both the optionless probe and explicit content requests to the pinned URL. Normal remote downloads are stored under that key. Browser-worker defaults disable local-model loading and filesystem cache. The per-worker metadata memoization key omits the template, but the template is set once before any request in a fresh, single-model worker; no runtime template-switch collision is introduced here.

An existing boundary remains: `checkCachedResource` tries `localPath` before the pinned remote key. A pre-existing unversioned local-path cache alias could therefore be returned; this patch does not purge or reject one. No such entry or incorrect cache hit was observed in this review. The Node FileCache branch also derives its default-revision key from `requestURL`, not the template, so this workaround must not be generalized to filesystem-cache consumers. These are limitations on universal cache-isolation claims, not a newly demonstrated regression in this browser-only fix. The focused test disables caches, and the planned cold metadata capture does not establish warm-cache behavior.
